## §2 AESV3復号レーン確立の技術メモ（第18676号全文抽出成功）

自環境（lab）で第309回ノート§4.1レシピを再構築し、次の修正点を確定した〔確認: テストベクトル2件（ユーザー所有不明の一般UID/OpenPasswordではなくfile/key両方の復号を含む）完全パス〕。

1. `PDF20._hash` 内のAES-128-CBCは **encrypt**（decryptは誤り）＝ EVP_EncryptInit 系で初期化する。
2. **UE/OE文字列の復号はAES-256-CBC IV=0**（ECBは誤り）。file key導出（Algorithm 2.B）・UE/OE とも訂正必須。
3. V5/AESV3の辞書内文字列（U・O・UE・OE）には**file keyを直接使用**（IVは先頭16バイト）。
4. Type0/Identity-H の2バイトコードは**元のAdobe-Japan1 CID**（charset fmt0のSID＝元CIDでも検証: 3174=東・1688=京等）。
5. UniJIS-UCS2-H の逆変換マップは **last-wins** で構築（first-winsだとKangxi部首の衝突で「月」→U+2F49へ誤変換）。
6. hex文字列は**4桁16進＝1CID**（2桁ずつ読むのはバグ）。
成果物: 18676.pdfのfile key **c67991cf** を再現し「令和8年11月26日（木曜日）東京都公報（第18676号）」本文全文を抽出。スクリプト一式は lab に保存済み（aesv3.py・koho_extract.py・koho_scan.py・cffparse.py・cid2uni.json.gz）＝第338回以降そのまま再利用可能。
